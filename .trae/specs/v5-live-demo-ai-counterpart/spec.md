# V5 增量：AI 虚拟用户 · 一键全自动演示 · 数据与视觉补齐 — 产品需求文档

## Overview
- **Summary**: 在已达 V4 基线（1 协调者 + 8 专家共 9 Agent、C1–C8 十剧本、控制台双主题）的校园二手交易 Multi-Agent 系统上，新增「AI 虚拟用户」与「一键全自动演示」能力：管理员点击一个演示按钮即可观看多 Agent 全自动协作直播；真人在议价室中可与由 DeepSeek 驱动的 AI 卖家/买家像真实同学一样聊天、议价、收回复；同时补齐各账号（含管理员）的商品/订单实例与主页商品图，并继续打磨世界顶尖水准的前端。
- **Purpose**: 解决当前三个可感知缺口——① 控制台「实时节点脉冲」静止时无事件，看不到多 Agent 自动协同；② 议价对方必须是另一个真人，发消息无人回复，系统"不活"；③ 管理员及部分账号「我的商品/我的订单」空白、主页存在无图商品。
- **Target Users**: 答辩演示者/研究者（一键演示、观察轨迹）、买家/卖家学生（与 AI 同学实时聊天议价）、平台管理员（终裁与监控）。

## Goals
- 控制台一个按钮触发**真实链路**（LangGraph + ACL + 黑板 + 三级决策）的全自动演示，全程节点脉冲/编排图/消息总线/冲突中心实时联动。
- 存在由 DeepSeek 驱动的虚拟 AI 账号，能模仿真实用户发布商品、在议价室中对真人的**文字消息与出价**给出拟人化回复，并能在授权策略内自动出价/接受成交。
- 每个可登录账号（重点：管理员 2400320321）打开「我的商品」「我的订单」都有丰富、状态多样、带真实图片的实例；主页在售商品数量与品类更丰富，零无图。
- 无 API Key 时全部新能力由 RuleLLM 确定性兜底，仍可完整演示（NFR-7 不回退）。
- 全部 V4 既有功能与测试保持绿灯。

## Non-Goals
- 不做真实支付、真实物流、真实校方身份对接、生产级高并发集群（沿用 V4 边界）。
- 不做语音/图片多模态聊天；AI 回复仅文本与价格出价。
- 不开放让 AI 自主决定退款/冻结等安全动作；安全否决与人工终裁权仍归规则与管理员。
- 不重写已有 9 Agent 内核契约与 10 个冲突剧本的断言口径。

## Background & Context
- 现状（已完成 V4）：9 个可插拔 Agent 均经 ACL 通信；`node_trace` 事件已在图节点 enter/exit 时经 WebSocket `/api/console/ws/control` 推送，但仅在用户手动触发流程的瞬间出现，刷新后无历史；议价室仅支持价格出价气泡（Offer），无自由文本消息；无 AI 账号字段；管理员账号无任何订单、无在售商品；库内 3 件商品 image_url 为空（其中 1 件在售导致主页破图）。
- 基础设施已就绪：EventBus（node_trace/message/counter/conflict）、RoomHub（议价室房间广播）、GraphRunner（start/resume）、DeepSeek 适配层 `chat_json`（超时重试+规则降级）、本地 `.env` 已配置用户提供的 DeepSeek Key（仅存本机，不入库不入日志）。
- 约束继承：FastAPI + Vue3 + Element Plus + SQLite(WAL) + LangGraph 1.x；单机 Windows；前端 Vite 5173、后端 Uvicorn 8000。

## Functional Requirements

### 演示与可观测
- **FR-101 一键全自动演示**：管理员控制台头部提供「▶ 一键演示」按钮；点击后后端启动唯一的后台演示任务，分阶段直播：AI 卖家发布普通商品（commodity→moderation 通过）→ AI 买家语义搜索 → 用户代理解析意图 → 多轮议价（含 AI 自动出价）→ 成交建单预占锁 → 风险检查/投票 → 自动支付 → 面交交付/收货 → 双向评价；另含一次违禁品发布触发安全 veto 的支线。每阶段在 WS 推送 `demo_phase` 阶段事件（阶段名、当前 thread、状态、文案）。
- **FR-102 演示任务管控**：同一时刻至多一个演示运行（再次启动返回 409 与当前进度）；提供运行状态查询与「停止」能力；每个阶段之间有可观看的节奏间隔（1.5–4 秒），但总时长 ≤ 90 秒；演示产生的商品/议价/订单全部真实落库（成为各账号可见数据）。
- **FR-103 前端演示观看体验**：演示启动后控制台自动呈现阶段进度（时间线/当前阶段高亮）、自动跳转「编排追踪」并跟随最新 thread、节点脉冲实时滚动、消息总线与冲突中心自动刷新；结束给出结果总结（成交单号、拦截事件、跳转链接）；停止/异常有明确反馈。
- **FR-104 节点脉冲历史回放**：服务端保留近期 node_trace 环形缓冲（≥100 条），新增只读接口；控制台加载后「实时节点脉冲」非空（展示最近真实事件），新事件实时前插，点击条目跳转对应编排实例。

### AI 虚拟用户
- **FR-201 AI 账号模型**：User 增加 `is_ai` 标识与 `ai_persona`（人设简介，如"大四数码摊主，爽快好说话"）；预置至少 2 个 AI 账号（AI 卖家「AI 校园摊主」、AI 买家「AI 同学」），均可登录体系内识别；前端在昵称旁显示 AI 徽章、议价室显示「AI 在线」状态。
- **FR-202 议价自由文本消息**：议价室新增自由文本聊天能力（新消息表 + REST 发送 + WS 房间实时广播 + 历史拉取）；消息与出价气泡视觉分层；仅议价参与方与管理员可读写。
- **FR-203 AI 拟人回复（DeepSeek）**：当议价对方为 is_ai 账号时，真人发送聊天消息或出价后，AI 在 2–6 秒内（带「对方正在输入…」实时指示）返回一条口语化短回复；回复由 DeepSeek 生成，上下文包含商品信息、双方出价、纳什价、剩余轮次/时间、AI 人设，并遵守：不暴露系统提示、不承诺系统外能力、价格立场符合其买卖角色。
- **FR-204 AI 策略出价**：AI 卖家/买家在对话策略点可自动发起价格出价（复用 negotiation Agent，严格满足单调让步、保留价与轮次/时限规则，违例由后端拒收）；价格达到可接受区间时可经既有成交逻辑成交并拉起交易流；AI 的文字回复与其出价动作一致（先说"行吧，48 给你"再出价）。
- **FR-205 降级与安全**：DeepSeek 不可用/超时/无 Key 时，AI 回复与出价自动切换 RuleLLM 确定性话术与规则让步策略，体验不中断；AI 不得触发越权动作（不能替用户支付、不能终裁、不能绕过审核）；所有 AI 消息正常落库审计。
- **FR-206 AI 商品供给**：AI 卖家名下始终有 ≥6 件在售、带真实图片、覆盖多类目、定价合理的商品，使真人随时可发起与 AI 的议价。

### 数据丰富度
- **FR-301 管理员数据**：管理员 2400320321 名下有真实历史：作为买家 ≥3 单（覆盖待支付/待收货/已评价等状态）、作为卖家 ≥4 件商品（含在售与已成交），含议价出价、评价或信用轨迹。
- **FR-302 全账号数据均衡**：张学长/李学姐/王同学/赵一鸣/钱多多等常用账号登录后均有「我的商品」或「我的订单」内容，订单状态合计覆盖 8 种状态机状态；议价列表非空。
- **FR-303 主页商品丰富化**：市场在售商品 ≥30 件，来自 ≥6 个不同账号（含 AI 卖家），覆盖全部类目；每件商品都有符合描述的真实图片（零无图、零破图）；清理现有无图在售商品（补图或下架）。

### 测试与质量
- **FR-401 自动化测试**：为演示编排、AI 回复/出价、聊天消息、脉冲历史接口、丰富种子新增 pytest；回归 10 个冲突剧本；全新无 Key 环境一键启动成功。
- **FR-402 前端品质**：遵循 frontend-skill——产品页重信息层级与克制动效，演示按钮与进度浮层、AI 议价气泡/打字指示、AI 徽章、市场卡片达到世界顶尖视觉水准；双主题控制台不回退。

## Non-Functional Requirements
- **NFR-1 可解释**：AI 每条自动回复/出价在审计或消息层可区分 `actor=ai`，演示阶段事件含触发的 Agent/节点信息。
- **NFR-2 一致性**：AI 出价同样受乐观锁与单调让步约束，并发下不产生超卖、非法状态迁移；既有 42+ 测试不回归。
- **NFR-3 及时性**：AI 文本回复 P95 ≤ 8 秒（含打字延时），超时即规则话术；演示阶段切换不阻塞 API 线程。
- **NFR-4 安全**：演示/AI 接口鉴权与数据隔离不变；API Key 不出现在响应体、日志与前端。
- **NFR-5 可复现**：断网/无 Key 下演示与 AI 议价可完整跑通 RuleLLM 路径。
- **NFR-6 稳定**：演示任务异常不致死服务，错误经 WS/状态接口可见；连续点击不产生并发脏数据。

## Constraints
- **Technical**: 仅可在现有 FastAPI/Vue3/LangGraph/SQLite 栈内增量；新增表通过 SQLModel metadata.create_all 自动建表（SQLite 零迁移）；后台任务用 FastAPI 事件循环 + asyncio（演示驱动同步图节点时放线程位，避免阻塞事件循环）。
- **Business**: 模拟环境、模拟支付；AI 回复内容需为健康的校园交易语境；演示节奏适合答辩现场观看（≤90 秒）。
- **Dependencies**: DeepSeek OpenAI 兼容接口（Key 已在本机 `.env`）；缺失时 RuleLLM 兜底。

## Assumptions
- 演示产生的数据保留在库中（作为真实业务数据与页面内容），不做"演示后回滚"；重复演示只会持续丰富数据，且幂等不产生重复违禁事件计数问题以外的脏状态。
- AI 回复使用 temperature 适中的非确定性文本，断言类测试仅验证规则路径与结构合法性，不断言 LLM 具体措辞。
- AI 账号可使用普通学号形态登录（演示/测试需要），但 UI 上清晰标注为 AI。

## Acceptance Criteria

### AC-1: 一键演示真实全链路直播
- **Type**: `rule`
- **Given**: 管理员已登录控制台且当前无演示运行
- **When**: 点击「▶ 一键演示」
- **Then**: 90 秒内依次收到发布审核→搜索→议价→建单→风险/投票→支付→交付→评价的 `demo_phase` 与 `node_trace` 事件，编排追踪出现对应新实例（含至少 1 个 veto 支线事件），结束后可在数据库/页面查到演示生成的在售商品与已支付订单
- **Pass Condition**: 浏览器实测一次演示全程无中断；后端 GET 演示状态返回 completed；相关商品/订单真实存在
- **Evidence**: 浏览器录屏/截图 + 接口响应 + 数据库查询

### AC-2: 演示互斥与可停止
- **Type**: `rule`
- **Given**: 演示正在运行
- **When**: 再次 POST 启动 / POST 停止
- **Then**: 启动返回 409 且不产生第二条流程；停止后状态为 stopped、不再产生新阶段事件
- **Pass Condition**: pytest 断言两行为
- **Evidence**: tests/test_demo_director.py

### AC-3: 节点脉冲加载即有历史
- **Type**: `rule`
- **Given**: 服务启动并发生过流程（播种演示流即产生）
- **When**: 打开控制台 Agent 总览
- **Then**: 「实时节点脉冲」通过历史接口渲染 ≥1 条真实事件，随后新事件实时前插
- **Pass Condition**: 接口返回非空且前端面板无空态
- **Evidence**: GET /api/console/traces 响应 + 截图

### AC-4: AI 议价文字消息拟人回复
- **Type**: `rule`
- **Given**: 买家与 AI 卖家存在进行中的议价会话
- **When**: 买家发送一条文本消息
- **Then**: 房间收到「正在输入」指示后，6 秒内收到 AI 的一条文本回复（有 Key 时为 DeepSeek 生成，无 Key 时为规则话术），消息落库且标注 from=AI
- **Pass Condition**: pytest（规则路径）+ 浏览器实测（配置 Key 的真实路径）各一
- **Evidence**: WS 帧序列 + NegotiationMessage 表记录

### AC-5: AI 自动出价合法且可成交
- **Type**: `rule`
- **Given**: 与 AI 的议价进行中
- **When**: 真人出价触发 AI 策略点
- **Then**: AI 出价满足单调让步与保留价约束（非法出价被后端拒收，AI 不会产生非法出价）；达到成交区间时按既有逻辑成交并拉起交易流
- **Pass Condition**: pytest 断言 AI 连续出价序列合法且一次完整 AI 议价可走到订单
- **Evidence**: tests/test_ai_counterpart.py

### AC-6: 无 Key 全功能降级
- **Type**: `rule`
- **Given**: 清空 DEEPSEEK_API_KEY 的测试环境
- **When**: 运行一键演示并与 AI 互发消息/出价
- **Then**: 全程无致命错误，演示 completed、AI 有回复、议价可成交
- **Pass Condition**: 隔离环境 pytest 通过
- **Evidence**: 测试日志

### AC-7: 管理员与全账号数据丰满
- **Type**: `rule`
- **Given**: 全新播种后的数据库
- **When**: 分别登录 2400320321 及 20240001–20240005
- **Then**: 管理员我的订单 ≥3、我的商品 ≥4；每个常用账号至少在商品或订单列表有数据；订单 8 种状态在全库均至少出现 1 次
- **Pass Condition**: API 计数断言
- **Evidence**: tests/test_seed_coverage.py

### AC-8: 主页商品丰富且零无图
- **Type**: `rule`
- **Given**: 全新播种
- **When**: 打开市场页
- **Then**: 在售商品 ≥30、来自 ≥6 个卖家账号、覆盖全部类目；所有在售商品 image_url 非空且 HTTP 200
- **Pass Condition**: API + 静态文件 200 检查
- **Evidence**: pytest/seed 断言 + 浏览器截图

### AC-9: 全量自动化回归
- **Type**: `rule`
- **Given**: 本期改动完成
- **When**: 运行 pytest 全量与 10 个冲突剧本及前端 build
- **Then**: pytest 全部通过（总数 ≥46）、10 剧本 PASS、npm build 零 TS 错误
- **Pass Condition**: 三条命令全绿
- **Evidence**: 命令输出

### AC-10: 演示观看体验与视觉品质
- **Type**: `rubric`
- **Dimension**: 演示控制台的信息编排、动效节奏与世界顶尖完成度
- **Scale**: 1-5
- **Anchors**: 1 = 按钮无反馈或数据错乱；3 = 能跑完但需手动切换面板、视觉平庸；5 = 一键后阶段时间线/跟随式编排图/脉冲/消息流全自动联动，动效克制高级，结束总结清晰可跳转
- **Pass Threshold**: >= 4
- **Evidence**: 浏览器实拍评审

### AC-11: AI 议价室对话体验
- **Type**: `rubric`
- **Dimension**: 议价室聊天的拟真度、打字动效、气泡层级与视觉质感
- **Scale**: 1-5
- **Anchors**: 1 = 回复机械/无动效/错位；3 = 能聊但气泡与出价混杂、AI 感明显；5 = 文字像真实校内同学、打字指示与气泡分层细腻、出价与聊天衔接自然，双主题均精美
- **Pass Threshold**: >= 4
- **Evidence**: 浏览器实拍评审

## Open Questions
- [x] 演示产生的数据是否保留？→ 保留，作为真实演示数据丰富页面。
- [x] AI 回复是否允许自由出价？→ 允许，但只能走与真人相同的议价规则接口，受全部约束。
- [ ] 演示按钮是否允许非管理员触发？→ 默认仅管理员（研究者用管理员账号答辩）；如你希望普通学生也能看演示，审批时告知。
