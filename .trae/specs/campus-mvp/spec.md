# 校园二手交易平台 Multi-Agent（简约版 / MVP）— 产品需求文档（PRD）

> 本文档由《软件需求规格说明书 V4》裁剪而来，服务于 AI 编码，是 MVP 实现的唯一需求基线。冲突机制、Agent 管理面板为核心研究内核，必须可见、可追溯。

## 1. 概述

### 1.1 一句话定义
一个可本机一键启动的校园二手交易 Web 原型：由 **4 个 Agent** 围绕"全局状态黑板（SSOT）+ 标准消息"协作，自动跑通"发布 → 审核 → 搜索 → 议价 → 下单 → 模拟支付 → 面交确认 → 互评"全链路，遇到冲突时按"**自动协商 → 协调者加权投票仲裁 → 人工 interrupt 兜底**"升级，安全类判定拥有**不可被投票/效用覆盖的一票否决权**。

### 1.2 产品是什么
- 后端：FastAPI + LangGraph 1.x + SQLite（WAL）+ SQLModel/Pydantic v2。
- Agent 通信：FIPA ACL 风格统一消息 Schema（performative 九类），经统一事件总线落库并向控制台实时推送。
- 前端：Vue 3 + TypeScript + Vite + Element Plus（深色 Mission Control 主题 + 浅色业务主题，同一套品牌设计基因）。

### 1.3 目标（G1–G5，本期保留）
- G1：4 个 Agent 权责清晰、经统一消息协作，端到端跑通交易主链路。
- G2：保留 Multi-Agent 研究内核的最小形态——多 Agent 意见冲突检测、加权投票仲裁、纳什参考价、安全否决、人工兜底全覆盖。
- G3：关键决策（审核/推荐/出价/风险/仲裁裁决）带依据与置信度。
- G4：系统提供 Agent 注册目录、编排流程实时图、ACL 消息流、黑板快照、冲突事件、Agent 暂停/恢复——即"多 Agent 是如何被管理的"全程可视化。
- G5：提供真实 DeepSeek LLM 与 RuleLLM 规则兜底双引擎，无 API Key 也能完整运行。

## 2. Agent 定义（共 4 个）

| # | Agent | 定位 | 关键输入 | 关键输出/决策 |
|---|---|---|---|---|
| ① | **协调者 Coordinator**（`coordinator`） | 接收全部请求并按 LangGraph 图编排；Agent 注册表与健康状态管理；冲突检测（锁/意见）；主持加权投票；通过 `interrupt` 把复核/终裁/暂停转交人工；纠纷申诉规则裁决 | thread_id、用户动作、各 Agent 上报 | 分派指令、流程跳转/熔断、裁决、人工转接 |
| ② | **商品审核 Agent（GoodsAgent，`goods`）** | 自然语言/表单商品信息结构化抽取（标题/类目/成色/属性）；违禁词+LLM 文本审核三档；建议价区间；商品上下架 | 卖家描述与图片 URL/占位、同类成交价 | 标准商品档案、approve/reject/manual/veto + 逐条依据 + 置信度 |
| ③ | **交易 Agent（TradeAgent，`trade`）** | 仅检索在售商品，按相关性/成色/价格匹配/卖家信用排序并给匹配理由；组织买卖双方多轮议价（保密保留价、5 轮/120 秒、单调让步、纳什参考价、授权区间自动出价、越界需确认）；成交触发下单 | buyer_id、item_id、双方底价、轮次、出价 | 排序列表+理由、纳什价、撮合价/破裂（推荐同类） |
| ④ | **履约信用 Agent（OrderCreditAgent，`order_credit`）** | 订单状态机+预占锁（乐观版本号+15 分钟超时）；沙箱支付跟踪；双向互评聚合、信用分动态更新、风险标签；向协调者/议价室输出带置信度的风险意见 | 成交请求、支付/交付/超时事件、评价、举报 | risk_level/confidence/basis、锁/解锁、信用分与标签 |

**统一契约**：所有 Agent 继承同一基类（`name/display_name/avatar/capabilities/health/llm_mode/handle()`），仅通过黑板与 ACL 消息交互，Agent 间不允许直接共享可变状态；新增一个遵循契约的 Agent 只需注册即可被图与控制台识别。

## 3. 功能需求（FR-1 ~ FR-12）

- **FR-1 账号与认证**：学号+bcrypt 密码注册/JWT 登录；冻结账号禁止交易类操作。
- **FR-2 商品发布与审核 Agent**：三档结论 approve/reject/manual/veto + 置信度 + 依据；驳回仅允许重提一次；veto 商品任何投票/效用/人工误操作都不得上架，人工仅可在"证据推翻违禁判定且填理由"时解除冻结（须留痕）。
- **FR-3 交易 Agent 搜索与议价**：搜索结果逐条给可展示匹配理由；纳什价、5 轮/120 秒、单调让步、超时破裂推荐同类、越保留价需前端确认。
- **FR-4 履约信用 Agent**：恰一单成交的乐观锁、抢单失败返回冲突错误与替代推荐、超时懒判定取消释放、支付幂等、面交状态迁移。
- **FR-5 协调者冲突检测与三级阶梯**：规则检测（锁/非法迁移/重复动作）；意见检测（支付前 OrderCredit 高风险 conf≥0.6）；加权投票（票权 0.5/0.2/0.3 × 置信度，±0.5 阈值）；interrupt 人工门。
- **FR-6 黑板 SSOT 与 ACL 消息**：类型化 LangGraph State + SQLite Checkpointer；出站消息经 Pydantic 校验，非法消息拒绝并留错误码；WS 推送五类事件。
- **FR-7 管理员工作台**：商品复核队列 + 纠纷终裁台，强制留痕，终裁写回驱动状态迁移与信用联动。
- **FR-8 LLM 双引擎**：DeepSeek（OpenAI 兼容）结构化 JSON，超时/非法输出重试 1 次后 RuleLLM 兜底。
- **FR-9 Web 前端**：五区块控制台为核心 + 买卖管理员三端完整页面 + WebSocket 实时。
- **FR-10 可解释与审计**：审核/推荐/出价/风险/投票/裁决依据在界面可见；订单审计时间线。
- **FR-11 视觉与交互设计标准**：统一设计 Token（靛蓝—青蓝渐变体系）、双主题、玻璃拟态、细腻微动效、空/载/错状态齐全；禁止 Element Plus 默认毛坯样式；控制台为暗色"指挥中心"质感。
- **FR-12 冲突剧本模拟**：CLI 一键运行 C1/C2/C6/C8，输出逐步轨迹与期望—实际对照表。

## 4. 数据模型（11 张表）

`user / item / negotiation / offer / order / review / appeal / acl_message / conflict_event / agent_status / audit_log`，关键字段与信用规则见正文；信用初始 100，好评 +2 / 中评 0 / 差评 -5 / 责任纠纷 -15 / 支付超时取消 -2；标签 new/normal/high_risk（阈值 80）。

## 5. 交易主链路与状态机

商品：草稿→待审核→（在售/驳回/人工复核/冻结）→被锁定→已成交/下架。
订单：已创建→待支付→已支付→待收货→（申诉中）→已完成→已评价；非法迁移一律拒绝；支付 15 分钟超时取消并释放锁。

## 6. 冲突机制（保留的最小研究内核）

1. 检测：规则检测 + 意见检测。
2. 三级阶梯：一级自动协商（议价让步/纳什参考，≤3 轮/120 秒）；二级协调者+相关 Agent 加权投票（Σ 票权×置信度×票值，≥+0.5 放行、≤-0.5 拦截、中间转人工）；三级 LangGraph `interrupt` 人工终裁。
3. 安全底线：GoodsAgent veto 高于一切，确定性规则优先于模型。
4. C1/C2/C6/C8 四个必做场景矩阵（议价僵持/并发抢单/高风险投票/违禁否决）。

## 7. 多 Agent 管理能力（FR-10/FR-9 控制台，本项目演示重点）

| 能力 | MVP 实现 |
|---|---|
| 注册与发现 | 启动自动注册 4 个 Agent；控制台展示名称/图标/职责/能力/契约信息 |
| 健康与模式 | runtime_status 呼吸灯（running/paused）、llm/rule 引擎标、消息/任务计数、最近活跃 |
| 编排管理 | 自定义 SVG 主链路节点图：实例已走节点发光、连线流光、当前/等待人工节点呼吸高亮、悬停节点 IO 摘要 |
| 消息监控 | ACL 实时流：performative 彩色标签、sender→receiver、置信度、过滤、payload 抽屉 |
| 黑板观察 | 选中实例 State 树形/JSON 双视图、interrupt 载荷、检查点列表 |
| 冲突管理 | C1/C2/C6/C8 时间线 + C6 投票明细（票值/权重/置信度/加权分仪表）+ 人工待办跳转 |
| 人工干预 | Agent pause/resume 开关：暂停后新业务友好挂起（409），恢复后继续 |

## 8. 技术栈与工程约束

FastAPI/Uvicorn、SQLModel、LangGraph 1.x（StateGraph + Checkpointer + interrupt + Command(resume)）、openai SDK、Pydantic v2、python-jose、bcrypt；Vue 3/TS/Vite/Pinia/Vue Router/Element Plus/lucide/ECharts/WSCSS/SQLite(WAL)；pytest + httpx。无 Redis/Postgres/Docker，不做高并发优化，单机功能正确性优先。

## 9. 非功能需求

NFR-1 双模式可运行；NFR-2 一致性（不重复成交/评价幂等，功能正确性）；NFR-3 LLM 稳健（重试→规则降级，无脏状态）；NFR-4 JWT/哈希/按用户隔离/veto；NFR-5 秒级响应宽松；NFR-7 决策可解释/可查；NFR-8 工程质量（类型注解、测试、一键启动，rubric ≥4）。

## 10. 验收标准

### 规则型
- **AC-1**：含违禁/欺诈规则的商品命中即冻结，任何后续投票/人工放行尝试无效（"证据推翻+理由"解除除外），证据直送人工。Evidence：C8 剧本 + 冻结商品上架接口拒绝 + audit_log。
- **AC-2**：种子账号依次完成发布→审核→搜索→议价成交→建单→模拟支付→交付确认→收货确认→互评，订单 reviewed、商品 dealed、信用分更新、全过程依据可查。
- **AC-3**：两路并发对同一商品成交/支付，恰一单成功，另一单收冲突错误并获替代推荐，无超卖。
- **AC-4**：正常成交落价在交集内、纳什价已算并展示、单调让步被强制、超轮次/超时破裂且推荐同类。
- **AC-5**：构造高风险支付冲突，投票明细落库，加权分 ≥0.5 放行 / ≤-0.5 拦截 / 中间转人工；resume 后订单正确迁移。
- **AC-6**：移除 Key 后主链路与 4 剧本全通过；预置 Key 时真实 LLM 链路成功。
- **AC-7**：Agent 间消息 100% 经 ACL 模型校验，缺字段/非法 performative/置信度越界被拒。
- **AC-8**：注入 LLM 超时/非法 JSON，重试后降级规则策略，DB 状态一致，无 500 脏状态。
- **AC-11**：执行业务时控制台五区块实时正确（计数增长、节点点亮、消息无遗漏、投票数字一致、暂停生效）。

### 评分型（1–5，阈值 ≥4）
- **AC-9 前端旅程**：三类角色核心页面完整性/交互反馈/错误提示清晰度。
- **AC-10 工程质量**：分层、契约一致性、配置化、测试、一键启动。
- **AC-12 视觉与交互**：设计 Token 统一性、控制台暗色氛围、动效质感、信息层次、空/载/错状态。

## 11. 开放问题（默认值）
1. 自动出价默认授权区间=保留价；2. 申诉直裁阈值 50 元；3. 控制台仅管理员可见。
