　01　本周学习笔记　

本周工作重心从后端转到浏览器，系统学习了 Vue3 组合式 API、Pinia 状态管理、axios 拦截器、路由守卫与 Element Plus 工程化，并实践了 WebSocket 客户端封装与前后端契约联调方法，首次让完整交易旅程在界面上走通。

1.1 Vue3 组合式 API 与 TypeScript

●　setup 语法：页面逻辑集中在 <script setup lang="ts"> 中组织，响应式状态用 ref/reactive 声明， computed 派生排序与倒计时，逻辑比选项式更聚拢。

●　类型贯通：后端 Pydantic 契约对应前端 interface，市场列表、议价消息、订单状态全部有类型提示，联调时字段写错当场报错。

1.2 Pinia 与 axios 拦截器

●　全局状态最小化：Pinia 只存登录态（token、用户信息、角色）与议价会话等跨页面状态，业务数据留在页面，避免全局 Store 膨胀。

●　拦截器收口：请求拦截器统一注入 JWT，响应拦截器统一解包 {code,msg,data}、弹出错误提示，401 自动跳登录，页面里不再写重复的鉴权代码。

1.3 Vue Router 路由守卫与角色分流

●　登录态守卫：未登录访问业务页一律重定向到 /login；登录后按角色默认落地（买家市场、卖家发布管理、管理员工作台）。

●　越权防护前后呼应：前端隐藏无权菜单只是体验层，后端角色守卫仍是最终防线，两边使用同一套角色枚举。

1.4 Element Plus 与设计令牌

●　设计令牌统一品牌：在 tokens.scss 中把藏蓝 1F3A5F、商务蓝 2E5C8A、金 C9A84C 映射为 CSS 变量，Element Plus 主题色覆盖为同一套蓝金体系。

●　表单校验复用契约：发布表单的必填项、价格区间、字数限制与后端 Schema 对齐，前后端双重校验给出一致的错误提示。

1.5 WebSocket 客户端与议价室 UI

●　可重连客户端：封装带自动重连的 WS 客户端，进入议价室时携带 JWT 加入房间，离线消息在重连后通过历史接口补齐。

●　实时交互细节：出价消息左右气泡分列、违例出价即时红条提示、顶部 120 秒倒计时、纳什参考价出现时金色高亮引导。

1.6 前后端联调方法论

●　契约先行：先在前端用接口类型与 Mock 数据把页面做完，再切换 Vite 代理指向真实后端，联调问题被压缩到字段与状态映射层。

●　按旅程串测：按“发布 → 审核 → 搜索 → 议价 → 支付 → 交付 → 评价”的真实顺序逐页联调，每通一环就回归上一环，防止改新坏旧。

1.7 ECharts 6 监控大屏预研

●　图表选型：预研折线（议价轮次与时长）、环形（冲突类型占比）、数字卡片（在线商品/成交/待办）三类图表，为 P1 监控大屏储备组件。

●　数据来自轨迹：大屏数据直接读取冲突事件与审计轨迹接口，不额外造统计口径。

1.8 前端路由建模与联调数据度量

●　路由即权限矩阵：把每个页面对应到允许访问的角色集合，画成“登录 → 主布局 → 三角色页面组”的路由地图；菜单隐藏与路由守卫共用这张矩阵，后端角色守卫做最终兜底。

●　用燃尽图管理缺陷：联调阶段按日记录累计发现/累计修复两条曲线，未修复缺口（两线之间面积）逐日收窄，D6 清零比“感觉改得差不多了”更有说服力。

●　漏斗定位流失环节：把交易旅程拆成曝光→详情→议价→成交→支付→好评六层漏斗，逐层算转化率，才能看出议价机制到底提升了哪一环，而不是只看总成交数。

2.3 卖家端：发布、管理与交付

●　智能发布页：标题/描述/价格表单带实时校验，提交后可看到 Agent 生成的类目、成色标签与建议价区间，审核结论与逐条理由即时回显。

●　商品管理：按状态（待审核/在售/被锁定/已成交/驳回/冻结）分区展示，支持在售商品改价与下架，驳回商品可补材料重提一次。

●　议价与交付：卖家可进入议价室参与还价，订单完成支付后在“待交付”列表确认校内面交，交付后等待买家收货与互评。

2.4 买家端：市场、议价室与订单信用

●　市场与详情：多条件检索 + 综合排序，每张商品卡展示匹配理由；详情页展示卖家信用与商品状态，仅在售商品可发起议价。

●　实时议价室：出价气泡左右分列、违例红条提示、倒计时与轮次可见，纳什参考价金色提示，成交后一键跳转支付。

●　订单与信用：模拟支付、确认收货、双向评价一条线走完，个人信用页展示信用分、风险标签与历史评价。

　03　存在的问题　

主链路可见可用之后，剩余工作集中在“管理者视角、稳定性与交付打磨”：

●　问题 1　管理员工作台仍是半成品：审核复核列表已有独立页面，但三级终裁、熔断接管、安全事件待办还未整合进统一工作台。

●　问题 2　监控大屏尚在预研：ECharts 组件验证可行，但黑板实时事件推送与图表布局还未实现，属 P1 范围。

●　问题 3　剧本缺少一键运行器：C1–C8 目前靠手工页面操作触发，需要“一键运行 + 期望结果对照表”支撑答辩演示。

●　问题 4　自动化测试覆盖不足：现有测试集中在并发锁与内核，接口与前端交互的回归测试还不成体系。

●　问题 5　WS 重连极端场景：弱网下频繁断线重连时偶发重复广播，需要加消息去重与序列号。

●　问题 6　一键启动与文档待整理：前后端需分别启动、环境变量与默认账号说明分散在代码里，新机器演示前需要一键脚本与 README。
