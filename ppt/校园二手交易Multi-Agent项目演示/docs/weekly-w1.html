　01　本周学习笔记　

本周是项目启动的第一周，学习重点围绕“多 Agent 系统（Multi-Agent System, MAS）理论”与“多 Agent 之间如何分工、如何做决策、如何处理冲突”两条主线展开，同时对校园二手交易场景进行了业务调研，为后续角色划分与机制设计打基础。主要学习内容归纳如下。

1.1 多 Agent 系统的基础概念

● Agent 的四个核心特性：自治性（Autonomy，可自主决策而非被动响应）、反应性（Reactivity，能感知环境并及时响应）、主动性（Proactiveness，可面向目标主动行动）、社会性（Social Ability，可通过通信语言与其他 Agent 协作）。

● 多 Agent 系统相对单体智能体的优势：任务可分解、职责单一便于迭代；多智能体并行处理，响应更快；单个 Agent 故障时系统可降级运行，容错性强；不同角色可独立使用不同模型、工具与知识库，更贴近真实组织的协作方式。

● 适用性判断：校园二手交易平台涉及发布、审核、搜索、议价、下单、评价、仲裁等多类目标不同的任务，且买卖双方天然存在利益博弈，是典型的适合多 Agent 架构的场景。

1.2 Agent 经典认知架构：BDI 模型

● BDI = Belief（信念）+ Desire（愿望）+ Intention（意图）：信念是 Agent 对环境和自身的认知；愿望是它希望达成的目标集合；意图是从愿望中选定并承诺执行的当前目标。

● 对本项目的启发：每个交易 Agent 都应显式维护“我知道什么（如商品状态、对方报价）、我要什么（如买家期望低价、卖家期望高价）、我当前承诺做什么（如本轮还价幅度）”，这样 Agent 的决策才可解释、可审计，也便于协调者 Agent 在冲突时读取各方立场进行仲裁。

● 架构流派：慎思式（重规划、慢但理性）、反应式（快但缺乏全局观）、混合式（分层，上层慎思、下层反应）。本项目拟采用混合式：审核、仲裁等关键决策走慎思链路，搜索、问答等走快速反应链路。

1.3 多 Agent 的组织结构与通信机制

● 两种基本组织形式：层级式（存在管理者 Agent，自上而下分派任务、汇总结果，控制力强）与对等式（Agent 地位平等、直接协商，灵活但易失控）。本项目确定采用“1 个协调者 + 多专家 Agent”的层级与对等混合结构：常规流程由协调者编排，议价等双边博弈环节由买卖双方 Agent 对等协商。

● 通信标准：学习了 FIPA ACL 与 KQML 两类 Agent 通信语言，其消息核心由“言语行为（Performative，如 request、inform、propose、reject）+ 内容 + 对话标识”构成，可作为本项目自定义消息协议的蓝本。

● 共享信息机制：黑板模式（Blackboard）由所有 Agent 读写共享工作区，适合维护全局交易状态；结合消息总线实现点对点通信，可兼顾状态一致性与通信效率。

1.4 协作协议与谈判机制

● 合同网协议（Contract Net Protocol, CNP）：协调者发布任务公告 → 各 Agent 投标（给出能力与报价）→ 协调者择优授标 → 中标者执行并回报。这一“招标—投标—中标”机制非常适合将搜索、审核、推荐等任务动态分派给最合适的 Agent。

● 讨价还价（Bargaining）：买卖双方 Agent 轮流出价、交替让步，学习了单调让步策略、时间压力策略（截止时间临近时让步加速），并初步了解纳什谈判解——当双方让步空间的乘积最大时达成的协议最接近公平，可作为议价 Agent 自动出价的理论依据。

● 拍卖机制：英式拍卖、密封拍卖等可作为二手平台“多人竞价同一商品”场景的备选撮合方式。

1.5 多 Agent 冲突检测与群体决策理论（本周学习重点）

● 冲突的四种类型：①资源冲突（多个买家争抢同一商品）；②目标冲突（如推荐 Agent 追求平台佣金、用户 Agent 追求买家实惠）；③知识/信息冲突（各 Agent 掌握的状态不一致）；④决策冲突（对同一笔交易的风险判断，信用 Agent 与交易 Agent 意见相反）。

● 冲突解决的三类基本路径：协商（Negotiation，当事方直接谈判）、仲裁（Arbitration，提交中立第三方裁决）、投票（Voting，多 Agent 按权重表决），三者可按成本从低到高分级使用。

● 群体决策方法：学习了加权投票、多数原则、效用函数（Utility Function）综合评分等方法；并认识到“安全类规则应具有一票否决权”，不能被多数票覆盖。

● 博弈论常识：非零和博弈、帕累托最优、触发策略（对欺诈行为的惩罚机制）等概念，可用于设计信用 Agent 的长期激励，让“诚信交易”成为 Agent 的占优策略。

1.7 校园二手交易业务调研

● 核心业务链路：商品发布 → 平台审核 → 搜索/推荐 → 咨询议价 → 下单支付 → 线下/校内交付 → 确认收货 → 双向评价；异常链路包括申诉、退换、纠纷仲裁。

● 校园场景四大痛点：信息不对称（商品描述失真）、信任缺失（陌生人交易顾虑）、议价低效（反复砍价消耗精力）、纠纷处理难（责任难界定、平台介入慢）。多 Agent 架构可由专门的审核、议价、信用、仲裁 Agent 分别针对性缓解。

　02　本周完成的项目内容　

本周按照“先定角色、再定协作、重点设计冲突决策”的思路，完成了需求分析、多 Agent 角色分配、协作流程梳理和冲突决策机制设计四项核心工作，产出物以设计文档为主，暂不涉及代码实现。

2.1 需求分析

● 功能需求：商品发布与智能审核、个性化搜索推荐、Agent 辅助双边议价、订单与交易状态管理、信用评价、纠纷在线仲裁、异常情况人工介入。

● 非功能需求：决策可解释（每次仲裁能给出依据）、状态一致性（同一商品不能被重复成交）、响应及时性（议价与下单秒级响应）、安全可控（违禁品与欺诈交易必须拦截）、可扩展性（后续可插拔新增 Agent）。

2.2 多 Agent 角色分配设计（本周核心成果）

2.3 系统总体结构与典型交易协作流程

● 总体结构：采用“用户层 — 协调层 — 专家 Agent 层 — 数据与工具层”四层结构。全部 Agent 围绕“全局状态黑板（SSOT）+ 消息总线”开展协作，系统总体架构如图 1 所示。

图 1 多 Agent 系统总体架构图（四层结构 + 黑板 / 消息总线）

● 典型交易主链路：卖家发话 → 用户代理 Agent 解析意图 → 商品管理 Agent 建档并给出定价建议 → 内容审核 Agent 过审（不通过则驳回/转人工）→ 上架 → 买家侧搜索推荐 Agent 完成匹配 → 议价谈判 Agent 组织双边多轮议价 → 成交后交易履约 Agent 锁定商品、建立订单、跟踪支付与校内交付 → 双方确认 → 信用评价 Agent 聚合互评、更新信用分。

● 异常链路：任一环节出现争议（审核申诉、议价僵局、货不对板、恶意退款等），由协调管理 Agent 打断主流程，转入 2.4 节的分级冲突决策机制处理，处理完毕再决定恢复或终止主流程。

2.4 多 Agent 冲突决策处理机制设计（本周核心成果）

冲突决策机制回答两个问题：冲突如何被发现？发现后按什么规则裁决？本周设计了“一套检测机制 + 三级处理阶梯 + 两类量化工具 + 一条安全底线”，总体流程如图 2 所示。

图 2 多 Agent 冲突检测与三级决策流程图

● （1）冲突检测机制：①规则检测：状态机校验（如商品已锁定仍收到下单请求即触发资源冲突）；②意见检测：多个 Agent 对同一对象输出带置信度的结论，结论不一致且置信度接近时触发决策冲突；③目标检测：各 Agent 的行动提案统一提交协调者做目标相容性检查；④信息检测：以黑板中的单一事实源（SSOT）为准，Agent 私有信息与其不一致即触发信息冲突。

（2）三级处理阶梯（处理成本由低到高，逐级升级、全程留痕）：

① 一级 · 对等协商 ② 二级 · 协调仲裁 ③ 三级 · 人工兜底

触发：冲突初发、当事 Agent 可直接谈判

方式：限时 3 轮内自动让步、给出纳什参考价、规则解释并允许补材料

出口：成功→全程留痕并恢复主流程；失败→升级二级

触发：协商失败，或多 Agent 对同一决策意见相左

方式：协调者主持，全局效用函数评分 / 相关 Agent 加权投票（乘置信度）

出口：出具含依据的裁决书（可回溯）；被拒→升级三级

触发：涉资金/违禁/校园安全，或金额超阈值纠纷

方式：立即冻结相关操作，仲裁 Agent 汇总证据包，提交管理员/校方

出口：人工终裁，结果写回黑板并联动信用处罚

（3）两类量化决策工具：

◆ 量化工具一 · 全局效用函数（Global Utility）

U = 0.25·用户满意度 + 0.20·交易成功率 + 0.30·平台安全性 + 0.15·公平性 − 0.10·处理成本

协调者在两难决策中比较各候选方案的综合效用，安全权重（0.30）最高；权重为本周经验初值，下周用模拟实验调参。

◆ 量化工具二 · 加权投票与置信度

对风险判断类决策冲突，由信用、审核、交易等相关 Agent 投票，票数按专业相关性赋权，且各票乘以该 Agent 的意见置信度；平票或分歧过大时升级为二级仲裁。

（4）一条安全底线（不可被投票或效用覆盖）：

▲ 安全底线 · 一票否决与熔断

内容审核 Agent 对违禁品、欺诈交易拥有“一票否决权”，任何投票或效用得分都不能覆盖该否决；协调者对异常 Agent 拥有熔断隔离权，被隔离 Agent 的职责临时收回协调者代管。

　03　存在的问题　

本周设计以纸面方案为主，在复盘和向老师汇报思路后，梳理出以下尚待解决的问题：

● 问题 1　角色粒度仍需权衡：9 类 Agent 职责清晰但通信链路较长，商品管理与内容审核、仲裁与信用评价之间存在少量职责交叉，后续需评估是否合并部分角色以降低通信开销。

● 问题 2　仲裁权重主观性较强：全局效用函数的五项权重（0.25 / 0.20 / 0.30 / 0.15 / 0.10）目前依赖经验设定，缺乏真实交易数据和对照实验支撑，合理性有待验证。

● 问题 3　通信协议尚未标准化：仅确定参照 FIPA ACL 设计消息，但消息字段（言语行为、置信度、超时、对话 ID 等）、异常码与各 Agent 输入输出契约尚未形成正式规范。

● 问题 4　大模型决策的不稳定性：议价、仲裁等环节依赖 LLM 生成结论，存在偏离策略、输出格式漂移甚至幻觉风险，需要设计输出约束、规则校验与失败重试机制。

● 问题 5　并发一致性方案待细化：多买家并发抢单仅确定了“加锁 + 优先级排序”思路，锁的粒度、超时释放、支付失败回滚等细节尚未设计。

● 问题 6　框架选型未经验证：LangGraph 与 AutoGen 的判断基于文档调研，未做最小原型实测，编排能力与开发成本仍属未知。

● 问题 7　缺少模拟数据：手头没有校园二手交易的真实样本，议价曲线、纠纷类型分布等难以量化，冲突场景测试只能先凭经验构造。
