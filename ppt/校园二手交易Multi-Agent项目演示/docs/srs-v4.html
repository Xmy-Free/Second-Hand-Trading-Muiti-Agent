二 引言

▍2.1 编写目的

本文档是“校园二手交易平台 Multi-Agent 系统”的软件需求规格说明书（SRS）V4 版，用于明确系统必须实现的功能、行为、约束与验收标准，作为后续概要设计、详细设计、编码实现、测试验收与答辩演示的统一需求基线。本文档已综合 V1–V4 四轮迭代的调研、角色设计、冲突机制设计与技术选型结论。

▍2.2 项目背景

校园二手交易核心链路为“商品发布 → 平台审核 → 搜索推荐 → 咨询议价 → 下单支付 → 校内交付 → 确认收货 → 双向评价”，异常链路包括申诉、退换与纠纷仲裁。经 V1 阶段调研，校园场景存在四大痛点：

编号 痛点 具体表现 针对性 Agent
P-1 信息不对称 商品描述失真、货不对板 商品管理 / 内容审核
P-2 信任缺失 陌生人交易顾虑，缺乏信用约束 信用评价 / 纠纷仲裁
P-3 议价低效 反复砍价消耗精力、容易谈崩 议价谈判 / 用户代理
P-4 纠纷处理难 责任难界定、平台介入慢 纠纷仲裁 / 协调管理

单一智能体难以同时承担目标相互冲突的多类任务（审核求严、推荐求撮合、议价求中立、信用求风险敏感）。本项目以多 Agent 分工协作，并将“冲突检测与群体决策机制”作为研究核心。

三 总体描述

▍3.1 产品定义

系统是一个可运行、可演示、可解释、可复现实验的校园二手交易 Web 平台原型：由 1 个协调管理 Agent 与 8 个专家 Agent 围绕“全局状态黑板（SSOT）+ 标准消息”协作，自动完成交易主链路；遇到冲突时按“对等协商 → 协调仲裁 → 人工兜底”三级阶梯升级，安全类判定拥有不可被覆盖的一票否决权。

▍3.2 用户角色与目标

用户角色 使用目标 关键操作
卖家学生 快速发布规范商品、获得定价建议、高效成交、申诉有门 发布、改价、议价、确认交付、评价、申诉
买家学生 找到匹配商品、由 Agent 辅助议价、安全下单、维权有据 搜索、议价、下单、模拟支付、收货、评价、申诉
平台管理员（校方） 人工复核与终裁、接管异常 Agent、审计全程留痕 人工复核、三级终裁、安全处置、熔断接管
研究者 / 演示者 一键运行冲突剧本、观察黑板与决策轨迹、调参实验 剧本运行、轨迹回放、权重对比

▍3.3 四层总体结构

层次 组成 职责
① 用户层 卖家、买家、管理员 通过 Web 界面发起操作、接收解释性结论与确认请求
② 协调层 协调管理 Agent（Coordinator） 任务编排、冲突检测、三级调度、效用评分、加权投票、熔断与人工转接
③ 专家 Agent 层 8 个可插拔专家 Agent 用户代理、商品、审核、搜索、议价、履约、信用、仲裁
④ 数据与工具层 黑板 SSOT、业务数据库、规则库、大模型适配层 状态持久化、检查点、确定性规则与 LLM 双通道能力
协作原则： 全部 Agent 围绕类型化黑板协作，Agent 间只通过 ACL 标准消息通信，不私自共享可变状态；黑板状态唯一、可查、可回放。

五 功能需求

功能需求编号 FR-1 ~ FR-15，覆盖账号、9 类 Agent 能力、消息协议、人工工作台、可解释审计、剧本模拟与 Web 前端。

编号 模块 需求描述（触发 → 处理规则 → 结果）
FR-1 账号认证 学号注册/登录；密码 bcrypt 哈希；JWT 签发与角色鉴权；内置种子账号（含 2400320321）；冻结账号禁止交易但可申诉。
FR-2 用户代理 Agent 自然语言意图结构化；维护画像与保留价；授权区间内自动出价，越界或成交前必须人工确认；意图不清时引导澄清。
FR-3 商品管理 Agent 描述结构化、自动分类与成色标签；基于历史成交价给建议区间（卖家可改）；建档后进入“待审核”；支持主动下架未锁定商品。
FR-4 内容审核 Agent 违禁词规则库 + LLM 双判定，输出 通过/驳回/人工复核 + 置信度 + 逐条依据；命中违禁欺诈即 veto 冻结，不可被覆盖；驳回允许补材料重提一次。
FR-5 搜索推荐 Agent 仅检索在售商品；综合相关性/成色/价格/信用/画像排序；每条结果给出匹配理由；方案须通过目标相容性检查，偏向佣金则重排。
FR-6 议价谈判 Agent 双边会话状态机；单调让步（买价不降、卖价不升，违例拒收）；时间压力；纳什参考价；默认最大 5 轮 / 120 秒；成交或超时破裂并推荐同类。
FR-7 交易履约 Agent 成交预占锁（锁令牌+乐观版本+超时点）；抢单按“下单时间→信用分→支付完成”裁决；订单状态机；模拟支付超时/失败释放锁并回滚；校内面交确认。
FR-8 信用评价 Agent 订单完成后双向评分（一单仅一次）；信用分按规则动态更新；输出风险标签；向审核/议价/订单/仲裁给出带置信度的风险意见。
FR-9 纠纷仲裁 Agent 汇总证据包（档案/议价/订单节点/评价/信用）；输出结构化裁决书（责任+依据+执行方案+置信度）；超阈值或涉安全升级人工；联动信用处罚。
FR-10 协调管理 Agent 任务分解与图编排、Agent 注册发现、状态监控；执行全部冲突检测与三级调度；熔断异常 Agent 并代管；interrupt 移交人工后恢复主流程。
FR-11 黑板与消息协议 类型化黑板由 LangGraph State + Checkpointer 承载；ACL 消息含 消息ID/对话ID/performative/收发方/内容/置信度/超时/异常码/时间戳；偏差自动纠正并记录来源。
FR-12 人工工作台 待办队列（商品复核、三级终裁、安全事件、熔断接管）；证据包查看；终裁写回黑板并驱动状态流转；人工动作强制留痕。
FR-13 可解释与审计 审核结论、推荐理由、出价依据、裁决书、冲突升级路径全程可查；基于检查点提供决策轨迹回放。
FR-14 冲突剧本模拟 内置 ≥10 个剧本覆盖 C1–C8；一键运行并输出逐步轨迹与期望结果对照表。
FR-15 Web 前端 通用登录/首页；卖家发布与商品管理/议价/交付/申诉；买家市场/议价室/支付/评价/信用；管理员工作台；P1 监控大屏。

▍6.2 三级处理阶梯

级别 触发条件 处理方式 升级出口

一级

对等协商

 冲突初发、当事 Agent 可直接谈判 限时 ≤3 轮自动让步、纳什参考价、规则解释、允许补材料 成功→留痕恢复主流程；失败→升级二级

二级

协调仲裁

 协商失败或多 Agent 意见相左 协调者主持：全局效用函数评分 + 相关 Agent 加权投票（票权×置信度） 出具含依据裁决书；被拒/分歧过大→三级

三级

人工兜底

 涉资金/违禁/校园安全，或金额超阈值 立即冻结相关操作；仲裁 Agent 汇总证据包提交管理员终裁 人工裁决写回黑板，联动信用处罚并恢复/终止流程

▍6.3 两类量化决策工具

◆ 全局效用函数 U ◆ 加权投票（含置信度）

U = 0.25·用户满意度 + 0.20·交易成功率 + 0.30·平台安全性 + 0.15·公平性 − 0.10·处理成本

安全权重最高（0.30）；权重写入配置，P1 支持界面调参做对比实验。

风险类决策由信用、审核、交易等相关 Agent 投票，票权按专业相关性赋权并乘以各自置信度。

平票或分歧过大时升级二级仲裁并暂缓支付。

▍6.4 安全底线

▲ 不可覆盖： 内容审核 Agent 对违禁品、欺诈交易拥有一票否决权，任何投票或效用得分均不得覆盖；协调者可熔断隔离异常 Agent 并临时代管。实现上确定性规则优先于模型输出。

九 验收标准（V4）

共 15 条验收标准：12 条 rule（客观二元条件）+ 3 条 rubric（评分维度，阈值 ≥4，满分 5）。

AC-5 rule 三级阶梯可升级且可回溯 二级裁决书 + interrupt 三级冻结 + 人工写回；C3/C4 轨迹
AC-6 rule SSOT 信息冲突自动纠正 偏差自动纠正并记录来源；C7 剧本日志
AC-7 rule 八类场景全覆盖 C1–C8 均有剧本且总数 ≥10；一键运行对照表

AC-9 rule Agent 可插拔 新增示例 Agent 不改协调核心即可被调用；注册测试
AC-10 rule 决策轨迹可回放 按检查点重放消息、结论、置信度与升级路径
AC-11 rule ACL 消息协议统一 字段齐备、非法消息被拒；Schema 校验单测
AC-12 rule LLM 故障不产生脏状态 非法 JSON/超时后重试降级或转人工；故障注入测试
AC-13 rubric 前端完成度与易用性 三类用户旅程完整、反馈清晰；1–5 分，阈值 ≥4
AC-14 rubric 决策可解释质量 四类结论“依据—置信度—结果”充分、裁决书完整；阈值 ≥4
AC-15 rubric 架构与工程质量 分层清晰、测试齐备、一键启动；阈值 ≥4
